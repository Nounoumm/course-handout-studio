# 课程讲义工坊

把学生的一次提问，扩展成一份**模块化、知识点齐全、可直接阅读和打印**的讲义，并同时产出 DOCX 与 PDF。

适用场景：学生说“帮我整理一份××讲义”“系统讲讲××”“做一份期末复习资料”“从零学××”，或希望把某个主题讲透并配练习。

---

## 一、先判断：要不要问，问什么

先看学生已经给了什么。**信息足够就直接做**，并在开头说明你的假设；只有关键信息缺失时才问，且**最多问一轮**。

需要确认的通常是四件事：

1. **主题与范围**：只讲某一章，还是整门课？
2. **水平与目的**：零基础、应试、考研、项目实践？这决定推导深度和习题难度。
3. **篇幅**：几页的速览，还是 20–40 页的系统讲义？
4. **模板与习题**：标准教材型 / 考前复习型 / 项目驱动型 / 双语对照型；要不要题、要多少。

推荐用 `ask_user_question` 一次给出选项（模板选项可先调用 `handout_templates` 获取），并给出推荐项。学生说“你看着办”时，按以下默认值执行：

- 模板：`standard`
- 章节：6–8 章
- 习题：基础 + 提高（`basic`）
- 语言：中文，关键术语附英文

---

## 二、章节怎么分：像教材，而不是像笔记

### 结构约束

- **模块 2–4 个**，每个模块 2–4 章；模块是“学习阶段”，不是装饰。
- **章 3–12 个**，每章 2–6 节，每节 600–1500 字。
- 章标题用名词短语（“函数的极限”“列表与切片”），不用“第一章 随便聊聊”“其他内容”“杂项”。
- 不要出现“第 0 章”“附录 A 之前先看这个”这类奇怪分章；附录只放术语表、参考资料、答案索引。
- 每章必须有：学习目标（3 条左右）、先修知识、若干小节、本章小结（3–5 条）、习题（4–8 道）。

### 顺序：先直觉，后形式，再应用

每一章按下面的“双螺旋”推进，这是本插件的默认教学法：

1. **引入**：一个具体问题、现象或图，让学生知道“为什么学这个”。
2. **定义**：严格的定义、符号、单位、适用条件。
3. **解释**：推导或直观说明“为什么成立”，可用对比、图示、反例。
4. **例题**：2–3 道，由浅入深，给出完整步骤而不只是答案。
5. **易错**：指出一个最常见的误解，用“易错”引用块呈现。
6. **小结与衔接**：回到学习目标，说明与下一章的关系。

### 中国教材 + 外国教材，各取所长

- 取**中文教材**的：知识链完整、术语统一、定义—性质—定理—例题—习题的层次、章节篇幅均衡。
- 取**英文教材**的：先直觉后定义、图解与类比、解释“为什么”、常见错误（common misconceptions）、现实应用、自测题。
- 具体做法：每个核心概念至少给一个**直观解释**和一个**严格定义**；每个公式说明**适用条件**；每章至少一个**反例**或**常见错误**。

### 模块划分建议

- 模块一“基础与直觉”：概念、表示、基本性质。
- 模块二“方法与工具”：核心方法、推导、典型例题。
- 模块三“应用与综合”：建模、综合题、跨章联系。
- 模块四“拓展与复盘”（可选）：历史、前沿、易错总复习。

不要为了凑模块把一章拆成两半。一个模块只有一章时，检查工具会警告，优先合并。

---

## 三、知识点必须齐全

每章写完后，对照下面的清单自查；缺哪项就补哪项：

- [ ] 核心术语：中文名、英文名、一句话定义
- [ ] 符号与单位（或代码中的类型/复杂度）
- [ ] 性质、定理、公式，以及各自的**适用条件**
- [ ] 方法的操作步骤（编号列表）
- [ ] 至少 2 道例题，含思路与完整解答
- [ ] 至少 1 个常见错误或反例
- [ ] 与前后章节的联系（在小结里点一句）
- [ ] 分层习题 + 参考答案

“知识点齐全”不是“字数多”。宁可每节讲透一个点，也不要把定义堆在一起不解释。

---

## 四、结合市面上的视频与公开课

学生往往同时在刷视频课。讲义应当**与主流课程的结构对齐**，而不是另起一套。

做法：

1. 需要时用 `web_search` 查该主题的公开课程大纲，例如中国大学 MOOC、学堂在线、国家高等教育智慧教育平台、B 站同名课程，以及 MIT OCW、Khan Academy、3Blue1Brown、Coursera 等。
2. 只借鉴**章节顺序、先修关系、例题类型**，不要复制课程文稿、字幕或教材原文。
3. 在 `appendix.references` 里列出真实链接，并注明“对应第几章 / 为什么推荐”。
4. **不确定或搜不到，就不要写**。绝不编造课程名、链接或作者。

讲义正文里也可以用一句话点出对应关系，例如“这一节对应公开课中‘极限的直观理解’一讲”，但不要整段照搬。

---

## 五、习题怎么出

按三层设计，按需裁剪：

- **基础题**：概念辨析、直接套用定义或公式。2–4 道。
- **提高题**：需要两步以上推理、迁移到新情境。2–3 道。
- **挑战题**：综合应用、开放问题、跨章联系。0–2 道。

要求：

- 每题都能独立作答，不依赖“上一题的结论”（除非明确说明）。
- 每题都给答案；答案要写出**关键步骤或易错点**，不能只有一个结果。
- 题干避免歧义；涉及计算时给出必要的数据和单位。
- 学生只要“少量题”时，只保留基础题；要“考试训练”时，提高题为主并加一组限时模拟。

## 六、规格文件格式

讲义由一个 JSON 规格描述，正文用轻量 Markdown。先用 `handout_scaffold` 生成骨架，再补全。

```json
{
  "schema": "course-handout/1",
  "meta": {
    "title": "讲义标题",
    "subtitle": "一句话副标题",
    "series": "课程系列名",
    "author": "讲师/机构",
    "date": "2026 年 11 月",
    "audience": "适用对象",
    "template": "standard",
    "include_toc": true,
    "include_answers": true
  },
  "preface": "可选：前言 Markdown；留空则自动生成",
  "modules": [
    {
      "title": "第一部分　基础与直觉",
      "description": "本模块解决什么问题",
      "chapters": [
        {
          "title": "第 1 章　标题",
          "objectives": ["目标 1", "目标 2", "目标 3"],
          "prerequisites": ["先修知识"],
          "lead": "可选：本章引入 Markdown",
          "sections": [
            { "title": "1.1　小节标题", "body": "Markdown 正文" }
          ],
          "summary": ["小结 1", "小结 2", "小结 3"],
          "key_points": ["可选的跨章核心要点"],
          "exercises": {
            "basic": ["基础题题干", { "q": "带提示的题", "hint": "提示" }],
            "intermediate": ["提高题"],
            "challenge": ["挑战题"]
          },
          "answers": ["第 1 题答案", "第 2 题答案"]
        }
      ]
    }
  ],
  "appendix": {
    "glossary": [["术语", "解释"]],
    "references": [
      { "title": "公开课名称", "url": "https://...", "note": "对应第 2 章" }
    ],
    "notes": "可选说明 Markdown"
  }
}
```

### 正文 Markdown 支持

- 段落（连续行会自动接成一段）
- `**粗体**`、`` `行内代码` ``（加粗里可以嵌代码）
- `- 列表`、`1. 编号列表`
- 围栏代码块 ```` ```python ... ``` ````
- 表格：`| 列 | 列 |` + `|---|---|`
- 引用块：`> 提示：...`、`> 易错：...`、`> 结论：...`
  - 标签支持：提示、注意、易错、结论、要点、思考、说明、警告
  - “易错/警告”显示为红色框，“结论/要点”为蓝色框，其余为黄色框
- 图片：`![图注](相对路径)`（只引用真实存在的本地图片）
- `### 小标题`：节内子标题

**公式**：不渲染 LaTeX。请用 Unicode 数学符号（∑、∫、√、≤、≈、Δ）和普通文本；复杂推导放进代码块对齐排版，或拆成多行文字说明。

### 写作建议

- 正文要“讲人话”：先给结论再解释，或先给问题再给方法，避免连续三段都是定义。
- 每节开头一句话说明“这一节解决什么问题”。
- 代码块保持短小（10–25 行），关键行用注释标出；长程序拆成“最小示例 + 完整版”。
- 表格用于对比（方法 A/B、正确/错误、复杂度），不要用表格代替正文。

## 七、工作流

1. **确认需求**（最多一轮），确定主题、水平、模板、章节数、习题规模。
2. **（可选）选模板**：调用 `handout_templates`，把选项和推荐理由告诉学生。
3. **生成骨架**：`handout_scaffold({ topic, audience, template, chapters, exercises })`。
4. **补全内容**：用文件编辑工具逐章填写。长讲义分多次编辑，每次只改一个章节，保持 JSON 合法。
5. **检查**：`handout_check({ spec_path })`。修掉 error；warning 里“正文偏短”“习题不足”要处理。
6. **生成**：`handout_build({ spec_path })`。默认同时产出 DOCX 与 PDF。
7. **交付**：用 `present` 同时给出 DOCX 和 PDF，并说明页数、章节结构、习题数量。
8. **迭代**：学生要求加题、改难度、换模板时，改规格文件后重新 build；不要新建一份重复讲义。

### 路径约定

- 规格文件：`handouts/<主题>.json`
- 成品：`handouts/<主题>.docx` 与 `handouts/<主题>.pdf`
- 文件名用主题，不要用 `untitled`、`final-final`。重名时工具会自动加序号。

---

## 八、交付前的质量检查

- [ ] 每章有学习目标、小结、习题、答案
- [ ] 每节正文 ≥ 400 字，全篇 ≥ 3000 字（速览型可放宽到 1500 字）
- [ ] 至少 2 个模块，每模块 ≥ 2 章（内容少时合并模块）
- [ ] 没有“待补充”“TODO”“示例文本”残留
- [ ] 术语首次出现给中英文，前后一致
- [ ] 公式/代码的适用条件写清楚
- [ ] 引用链接真实可访问；没有编造
- [ ] 习题答案数量与题目数量一致
- [ ] `handout_check` 无 error；warning 已逐条判断
- [ ] 生成后打开 PDF 首页与目录，确认标题、章节、页码正常

---

## 九、边界

- 不复制受版权保护的教材章节、课程字幕或题库；用改写、自拟例题和公开链接。
- 不伪造引用、课程名、数据或实验结果。
- 涉及医学、法律、金融等高风险内容时，明确写“仅供学习参考”，不替代专业意见。
- 学生要求“押题”“泄题”时拒绝，改为按考纲整理知识点与题型。
- 生成的文件放在工作区内；不要写到系统目录。
